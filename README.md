# ⏱ 时间戳/Cron工具

## 简介

零AI、纯本地运行的时间戳转换与 Cron 表达式工具，面向开发者/运维场景中"语法记不住、每次都要查"的高频需求。所有计算均在浏览器内完成，不上传任何数据，无需 API Key。

## 功能

### Tab1：时间戳互转

- **当前时间**：每秒自动刷新显示当前 Unix 时间戳，支持一键复制 / 一键填入下方转换框
- **时间戳 → 日期**：自动识别 10 位（秒）/ 13 位（毫秒），输入框对非数字字符（空格、逗号、引号等日志中常见的脏字符）实时过滤，方便直接从日志/监控平台粘贴
- **日期 → 时间戳**：选择本地日期时间，输出对应的秒级/毫秒级时间戳
- **多时区对照**：UTC / 北京·上海 / 东京 / 美西 / 美东 / 伦敦，一次性列出同一时刻在各时区下的墙上时间
- **代码片段**：JavaScript / Python / Java / Go 四种语言获取与转换时间戳的示例代码，锁定某个时间戳后会动态替换进代码字面量，复制即可直接运行调试

### Tab2：Cron 工作台

- **运行时区选择器**：Cron 表达式里的时间必须绑定一个时区才有意义（"凌晨2点"在新加坡服务器和美东服务器执行的是两个完全不同的绝对时刻）。默认根据浏览器自动检测时区，可手动切换为表达式实际运行所在的服务器时区
- **表达式解析**：标准 5 位（分 时 日 月 周），支持 `*`、范围（`1-5`）、步长（`*/15`）、范围+步长组合（`1-30/10`）、逗号枚举（`1,3,5`），字段拆解可视化展示
- **人类可读描述**：将表达式翻译为自然语言描述，并标注所基于的运行时区
- **未来执行时间预测**：计算未来 N 次（5/10/20 可选）触发时间，点击任意一条可联动跳转回 Tab1 查看对应时间戳
- **引导式生成表单**：不依赖 AI，纯结构化下拉选择（每天/每周/每月），选择不同频率时自动互斥锁定冲突字段，避免拼出逻辑歧义的表达式

## 技术要点

- **DOM/DOW 的 OR 逻辑**：Linux crontab 规范中，若"日"(DOM)与"周"(DOW)字段同时被显式指定（两者都非 `*`），两者关系是"或"而非"与"——这是配置定时任务时最常见的误判点，本工具在解析引擎中正确实现，并在人类可读描述区域常驻黄色警示提示
- **时区感知计算**：不依赖运行此页面的浏览器/服务器本地时区，而是用 `Intl.DateTimeFormat` 把 UTC 时间戳翻译成用户选定时区下的日历字段再做匹配，遍历游标本身用 UTC 毫秒数推进，避免引入夏令时（DST）偏移错误
- **月末边界处理**："每月31号"这类在 2 月不存在的日期组合会被正确跳过，不报错也不卡死
- **同步计算性能保护**：执行时间预测的遍历上限设为 2 年（约 105 万次循环），控制最坏情况（表达式指定了永不存在的日期组合）下的同步阻塞时长在毫秒级，不阻塞主线程
- **等宽数字排版**：所有动态刷新或密集排列的数字（当前时间戳、多时区表格、Cron 预测列表、人类可读描述）统一使用 `font-variant-numeric: tabular-nums`，避免数字宽度不一导致的视觉抖动

## 不做的（v1 明确排除）

- 不支持秒级 Cron（Quartz 6 位写法）
- 不提供 AI 自然语言生成 Cron（用结构化表单代替）
- 不支持自定义时区数据库（仅使用浏览器原生支持的 IANA 时区列表）

## 测试覆盖

- Cron 解析引擎：36 个单元测试，覆盖 OR 逻辑陷阱、步长语法、月末边界、非法输入校验等场景
- 时区感知计算：12 个单元测试，验证同一表达式在不同时区下产生不同绝对时刻且能正确还原
- 端到端测试（Playwright）：覆盖 Tab 切换、输入解析、表单互斥、跨 Tab 跳转、深色模式等完整交互链路，全程无 JS 报错
